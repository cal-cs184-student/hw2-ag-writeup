Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

Ok, so the simplest way I can think to put it is that a bezier curve is defined by a bunch of control points and a parameter t, and doing repeated lerps allows us to find the point on the curve at point t. There must be n+1 control points, because each step we lerp between each pair of naighbors and lose one point in the process, until we get down to just 1.

Part 2: Bezier surfaces with separable 1D de Casteljau

Bezier surfaces are simply a curve of curves, a series of curves all lined up along curves, so if we break it up into those little pieces we already know how to use de Casteljau on a curve. So we take each row of control points, each representing a bezier curve in u, and evaluate every row at u collapsing each row into a point. We've taken a nxn grid and turned it into n points, which define a bezier curve in v which we evaluate to get our point!

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

To compute the normal at a vertex I traverse the halfedge structure to find every face that touches it. I start at the outgoing half edge and check each face I find to make sure it is not a boundary, then computer the cross of p1-p0 and p2 - p0, p0, p1, and p2 being the vertex positions of each face. The direction of the cross product is the face normal and the length is twice the area of the triangle so I never need to compute areas, I just sum cross products until I return to the original halfedge. I then normalize my cross product sum to a unit vector.

Part 5: Edge split

Split starts the same way as flip: if either neighboring face is a boundary I just return, otherwise I label everything in triangles abc and cbd (h0 - h9, a b c d, e1 - e4, f0 and f1) before touching anything. The difference is that split actually makes new stuff: one new vertex m at the midpoint of b and c, three new edges (a-m, b-m, d-m), two new faces, and six new halfedges. The original edge gets reused as the m-c half, so I end up with four triangles: mca, mab, mbd, and mdc. Then just like flip I use setNeighbors on all twelve inner halfedges and reset the halfedge pointer of every vertex, edge and face. A nice sanity check is that I add 1 vertex, 3 edges and 2 faces, and 1 - 3 + 2 = 0 so the topology doesn't change. I also set the isNew flags here for part 6: m is new, a-m and d-m are new edges, and the two halves of the original edge are old.

Part 6: Loop subdivision for mesh upsampling

I did this in three steps. First, on the original mesh, I compute where everything is going to end up without actually moving anything yet. For each old vertex I walk around it to get its degree n and the sum of its neighbors, then store (1 - n*u) * position + u * neighbor_sum in newPosition, where u is 3/16 if n = 3 and 3/(8n) otherwise. For each edge I store 3/8 * (A + B)+ 1/8 * (C + D) in the edge's new position, where A and B are the endpoints and C and D are the opposite vertices. I can't update position during this step because then later vertices would be averaging neighbors that already moved. Second, I copy all the original edges into a vector otherwise I'd keep splitting the new edges forever, split each one, and hand the edge's precomputed position to the new vertex. Then I flip every new edge that connects an old vertex to a new one. Third, I copy newPosition into position for every vertex. My biggest bug was having the flip condition backwards, so it was flipping the halves of the original edges instead of the new ones, which turned the mesh into garbage.

subdivision iterations

After a few iterations the mesh gets smoother, but sharp corners and edges get rounded off and the whole thing shrinks a bit. That's because loop subdivision keeps moving every vertex toward an average of its neighbors, and corners are the farthest from that average so they get pulled the most. Pre-splitting the edges around a corner helps, since the new vertices are close to the corner, so the averages use nearby points and the corner stays sharper.

corner with and without pre-splitting

The cube gets lopsided because each square face is split by just one diagonal, and those diagonals aren't arranged symmetrically. So some corners have more neighbors than others, and since the loop weights depend on degree and neighbors, those corners get pulled harder in certain directions. To fix it I split the diagonal of every face before subdividing. Now every face is four triangles around a center vertex and every corner has degree 6, so everything looks the same locally and the cube subdivides symmetrically.
